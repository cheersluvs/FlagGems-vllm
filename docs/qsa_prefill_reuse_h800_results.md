# H800 key-major 8-warp 配置试验结果

[原始报告](https://github.com/cheersluvs/FlagGems-vllm/blob/4b77a6f0726549275bc5d928e513b092499aa30e/results/qsa_select_paged_prefill/h800/flagtree134-ab-20261020-075033/stage-summary.json)；代码b60b59f；242 passed、1 skipped（需第二张SM90卡），22组全部完成。
结论：保留八配置私有候选作为下一轮基线；暂不替换生产入口。增量收益主要来自上游长prefill，新增推理组没有选用新配置。
58个文件通过Git blob/长度校验；44份源码快照与测试代码相符；预检、正确性和22个worker编译器/GPU/原生扩展身份一致。
严格空闲卡模式，102个阶段、612个原始计时样本、408次计时遥测均通过。两组选全仅测pipeline，score/TopK为N/A。

## 资源证据与限制

例如n1/q16384/p51200原key-major为TR64/BN64/KT16/warps4，232寄存器/线程、106496共享字节、0 spill；
候选同TR/BN/KT、warps8为118寄存器/线程、114688共享字节、0 spill。本case增量1.07049×。
每线程寄存器约减半，但warp/线程数翻倍，每CTA寄存器不能据此说减半；共享内存反而增加8192字节。
只能确认分工变化和实测收益，不能在无硬件计数器时断言occupancy、DRAM流量或瓶颈。ncu/nsys仍不可用。

## 测量环境和耗时

GPU UUID GPU-2d17872f-4327-2beb-8049-604ecf6a3d66；FlagTree实际模块3.6.0，ptxas13.4.59、CUDA13.4兼容libcuda。温度32–52C，SM时钟1965–1980MHz。
3轮、warmup200ms、rep100ms，初始温度门槛80C。24次准入通过，另有一次滞后利用率超限等待10秒后通过；没有温度等待。
完整正确性514.82秒（8分35秒）；首末benchmark遥测跨度1015.80秒（16分56秒），包含case间编译/启动/验证和计时。
上一轮相应跨度1929.79秒，本轮下降约47.4%，尽管增加了20个直接增量对照阶段；这不是严格同工作量的总耗时对照。
