## 后续策略：常规2轮，边界额外确认

同编译器stage runner默认rounds由3改为2，显式--rounds仍可覆盖。保持一次baseline→candidate及一次candidate→baseline，保持warmup200ms、rep100ms、实际thermal/PID守卫、完整正确性以及TopK明细。
--rounds1仍可用于初筛；一次do_bench内部仍有反复执行和中位数，不等于只启动一次kernel。但1轮无法检查外层重复性，也没有反转测量顺序，不能单凭这一轮对接近阈值的case作最终判断。
后续若某case加速比接近0.98/1.0、涉及小幅keep/revert，或两轮差异明显，应对这些case增加到3–5轮，避免全30组一律增加轮数。每个新kernel/工具链/workload需重新观察波动。
本次已有三轮报告直接保留，无需为了使用新默认轮数重跑。性能目标、数值容差、工作负载、TopK以及生产源码/配置都不在这次轮数调整中改变。

## 为什么只减少rounds不能大幅缩短总时间

从机器日志的首次准入08:24:53到末次计时遥测08:59:33约34分40秒，不包括完整上传流程。日志中可核对的区间如下：

| 项目 | 秒 | 解释 |
|---|---:|---|
| 完整正确性pytest | 621.52 | 219通过、1跳过 |
| 首末benchmark遥测跨度 | 1364.87 | 约22分45秒，含case间工作 |
| 各阶段before_timing→after_round3累计 | 406.26 | 约6分46秒，含计时和监控开销 |
| 第三轮区间累计 | 136.15 | 3→2轮可省时间的近似参照 |
| 同worker阶段间区间 | 53.93 | 含验证、落盘等 |
| 相邻worker遥测间隙累计 | 904.68 | 含退出/启动/import/JIT/调优/验证/准入等 |
| 已记录利用率等待 | 20.00 | 无进程的7%/8%残留利用率，已含在相关间隙中，不另加 |

3→2轮预计只省约136秒（2分16秒），相当于上述总日志跨度约6.5%；不能声称总耗时减少三分之一。轮数变化会影响后续温度/缓存/调度，实际节省仍须以后续日志确认。
约15分钟落在worker间隙，当前日志不能准确分离其中编译、调优、导入等各项成本。下一步若继续压缩墙钟时间，应先增加这些阶段的耗时记录，再评估复用编译缓存、减少重复初始化或区分候选初筛与最终全量验证；这次不削弱正确性或更改进程隔离。
